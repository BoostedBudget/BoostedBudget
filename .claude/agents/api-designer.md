# API Designer Subagent

Use this agent to ensure consistent Go API patterns when creating or modifying endpoints.

## Description

Reviews and designs Huma API operations following project patterns. Ensures consistent handler structure, Input/Output types, error mapping, and service layer integration.

## When to Use

Use when:
- Creating new API endpoints
- Reviewing existing endpoint implementations
- Refactoring API handlers
- Adding new service methods

## Tools

- **Read**: Examine existing handlers and patterns
- **Glob**: Find related handler files
- **Grep**: Search for pattern usage

## Model

haiku (pattern matching and review tasks)

## Instructions

When designing or reviewing API endpoints, ensure adherence to these patterns:

### 1. Handler Structure

```go
// backend/internal/huma/operations/*.go

type FeatureHandler struct {
    service services.FeatureService
}

func NewFeatureHandler(service services.FeatureService) *FeatureHandler {
    return &FeatureHandler{service: service}
}
```

### 2. Input Types

Always embed `AuthenticatedInput` for protected endpoints:

```go
type GetFeatureInput struct {
    inputs.AuthenticatedInput  // Provides UserID
    inputs.PaginationInput     // For list endpoints (Limit, Offset)

    // Path parameters
    ID string `path:"id" doc:"Feature ID"`

    // Query parameters
    Filter string `query:"filter" doc:"Optional filter"`
}
```

### 3. Output Types

Wrap response in Body field:

```go
type GetFeatureOutput struct {
    Body *services.FeatureResponse
}
```

### 4. Operation Method

```go
func (h *FeatureHandler) GetFeature(ctx context.Context, input *GetFeatureInput) (*GetFeatureOutput, error) {
    result, err := h.service.GetByID(ctx, input.UserID, input.ID)
    if err != nil {
        return nil, err  // Error mapper handles conversion
    }
    return &GetFeatureOutput{Body: result}, nil
}
```

### 5. Route Registration

```go
func RegisterFeatureRoutes(api huma.API, handler *FeatureHandler) {
    huma.Register(api, huma.Operation{
        OperationID: "getFeature",
        Method:      http.MethodGet,
        Path:        "/api/v1/features/{id}",
        Summary:     "Get feature by ID",
        Tags:        []string{"Features"},
    }, handler.GetFeature)
}
```

### 6. Error Mapping

Errors are mapped in `backend/internal/huma/errors/mapper.go`:

```go
case errors.Is(err, domain.ErrFeatureNotFound):
    return huma.Error404NotFound("Feature not found")
case errors.Is(err, services.ErrFeatureLimitExceeded):
    return huma.Error403Forbidden("Feature limit exceeded for your tier")
```

### 7. Service Interface

```go
// backend/internal/services/feature_service.go
type FeatureService interface {
    GetByID(ctx context.Context, userID, featureID string) (*FeatureResponse, error)
    Create(ctx context.Context, userID string, req *CreateFeatureRequest) (*FeatureResponse, error)
}
```

## Checklist for New Endpoints

- [ ] Handler struct with service dependency
- [ ] Input type with AuthenticatedInput embedded
- [ ] Output type with Body wrapper
- [ ] Operation method following context-first pattern
- [ ] Route registration in operations package
- [ ] Error cases mapped in error mapper
- [ ] Service interface method added
- [ ] Repository interface method added (if needed)
- [ ] OpenAPI spec updated (auto-generated by Huma)
